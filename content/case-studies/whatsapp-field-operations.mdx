## A growing business, routed through one phone

The company builds, waterproofs, renovates and maintains swimming pools. With 505 projects behind it and more than 150 people on the payroll, it runs several live sites at once while maintenance technicians work through recurring customer visits.

All of that coordination ran on WhatsApp: personal chats, one group per site, forwarded photos and voice notes. That works for a team of ten. At 150 people it meant every question, update and approval passed through the owner. The owner had become the company's router.

### A typical morning, before

- Calls to find out who reached which site, and who didn't.
- Progress photos arrive in five formats across five chats.
- A customer asks for an update the owner has to go and chase.
- A maintenance visit nobody wrote down gets missed.
- A supervisor's end-of-day report lands after the problem has grown.

## Our approach: build where the team already lives

The obvious fix was a field-service app. We didn't build one. Site crews already had WhatsApp open all day. Any new app would need a download, a login and training, and adoption on site is where those tools usually fail.

So the brief became: keep every conversation on WhatsApp, and put an operations layer behind it that captures, sorts, chases and reports.

<CardGrid>
<Card kicker="Principle" title="Don't move the crew">Workers check in, send photos and close tasks by replying to messages. One tap, a photo, or the word "done". No app, no password, no training session.</Card>
<Card kicker="Principle" title="One agent, one job">Each agent owns a single workflow: attendance, site photos, tasks, reminders or customer updates. Small agents are easier to test, explain and fix than one agent that does everything.</Card>
<Card kicker="Principle" title="The owner handles exceptions, not traffic">Routine messages are logged and filed without anyone reading them. Only what's late, missing or off-site reaches a manager's screen.</Card>
<Card kicker="Principle" title="Prove it on a few sites first">Core check-ins and tasks went live with a pilot group before the dashboard and customer-facing automation were added. Each phase had to work before the next one started.</Card>
</CardGrid>

## How it's put together

Five layers. People stay on WhatsApp at the top. Everything below them is invisible to the crews.

| Layer | What's in it |
| --- | --- |
| People | Site crews, supervisors, maintenance techs, customers |
| Channel | WhatsApp Business Platform: utility templates, interactive reply buttons, location messages, photos, video and voice notes |
| Agents | Check-in, site-update, task, nudge and client agents, sharing sender lookup, message routing, a scheduler and escalation rules |
| Data | Operations database (employees, sites, tasks, check-ins, reports, customers, contracts) and a media archive of photos and video by site and date |
| View | Manager view (owner dashboard): who is where, what is late, which site needs a call, maintenance this week |

### The life of one message

1. **Receive.** A crew member replies, taps a button or sends a photo.
2. **Identify.** The phone number is matched to an employee, their role and today's site.
3. **Classify.** Check-in, site photo, task update or free text, so it goes to the right agent.
4. **Store.** Saved with site, person, date, time and stage. Photos go to the archive.
5. **Act.** The dashboard updates, follow-ups are scheduled and overdue items get flagged.

## The six agents

### Agent 01: Check-in agent

Starts every working day. At 6:30 AM each worker gets a message with today's site and a one-tap check-in. The reply is timestamped when it arrives. A shared location and a site photo confirm the worker is physically there, which stops friends checking in for each other.

- **Trigger:** scheduled, 6:30 AM, every worker on today's roster
- **Crew effort:** one tap, then share location and a photo
- **Captures:** arrival time, location, photo, assigned site
- **Escalates:** missed check-ins go to the nudge agent, then to the manager view

### Agent 03: Task agent

A manager creates a task with a site, an owner and a deadline. The worker gets it as a clear WhatsApp message and replies as the work moves. Every task carries a status, so "did anyone order the pump?" has an answer without a phone call.

- **Statuses:** pending, in progress, delayed, done
- **Crew effort:** tap a status, or reply "done" with a photo
- **Captures:** owner, site, deadline, status history, proof photo
- **Escalates:** past-deadline tasks go to the nudge agent and the manager view

### Agent 04: Nudge agent

Chases anyone who is late on a check-in, a photo report or a task. Politely first, then less politely. If the reminders don't work, the item goes to a manager. Managers stop making chasing calls and only see what is still outstanding after the agent has tried.

1. Friendly reminder to the person.
2. Firmer reminder, naming the overdue item.
3. Flagged to the supervisor and shown on the manager view.

The sequence stops as soon as the missing item arrives.

### Agent 05: Client agent

Keeps customers informed without the owner writing a single message. When a build stage closes, the customer gets a short update with photos. Maintenance customers get a reminder before each visit, a recap after it, and notice before their contract renews.

- **Stage updates:** sent when a project stage is marked complete
- **Visits:** reminder before, recap after, with a confirm button
- **Renewals:** reminders ahead of contract expiry

## How a working day runs now

The schedule runs itself. People only step in when something is late or missing.

1. **6:30 AM, check-in.** Every worker gets today's site and a one-tap check-in.
2. **Morning, tasks out.** Managers assign jobs. Workers get them on WhatsApp.
3. **Mid-shift, photos #1.** Supervisors get the first photo request for each site.
4. **Ongoing, nudges.** Anything late is chased automatically, then flagged.
5. **End of shift, photos #2.** Second photo request. Tasks closed with proof.
6. **Any time, owner view.** Exceptions only: who is missing, what is late.

## Rules and safeguards

The agents follow a small set of rules. Each one turns an event into an action, so nobody has to remember to ask.

| Event | Rule |
| --- | --- |
| Start of day | Check-in message at 6:30 AM to every worker rostered that day |
| Missed check-in window | Nudge step 1, then step 2, then shown as missing on the manager view |
| Each active site | Two photo requests per day to the site supervisor |
| Task passes its deadline | Status set to Delayed, nudge sequence starts, shown on the manager view |
| Project stage marked complete | Client agent sends a stage update with the latest photos |
| Maintenance contract nearing expiry | Renewal reminders to the customer, renewal flagged to the owner |

## Message types and data model

Every interaction uses a native WhatsApp Business Platform message type, so it looks like a normal chat on the worker's phone.

| Job | WhatsApp feature | Why it's used |
| --- | --- | --- |
| Morning check-in | Approved utility template | Business-started messages outside the 24-hour customer service window must use a pre-approved template. |
| One-tap replies | Interactive reply buttons | Up to three fixed choices per message: structured answers, no typing. |
| Proof of presence | Location message and photo | Location is compared with the assigned site. The photo stops proxy check-ins. |
| Site reports | Image, video and voice | Supervisors report as they always did. The system tags and files each item. |
| Customer updates | Utility templates with media | Stage updates and visit reminders sent under the company's business name. |

Platform rules as documented by Meta for the WhatsApp Business Platform (Cloud API).

| Record | Key fields | Written by |
| --- | --- | --- |
| Employee | Name, phone number, role, crew, active flag | Admin setup. Phone number is the identity key |
| Site | Name, location, customer, current stage, assigned crew | Managers |
| Check-in | Employee, site, timestamp, location, photo, on-time flag | Check-in agent |
| Site report | Site, supervisor, stage, media links, note, timestamp | Site-update agent |
| Task | Title, site, owner, deadline, status history, proof photo | Managers and task agent |
| Customer | Name, phone number, site or contract, update preferences | Office |
| Maintenance contract | Visit frequency, visits done and remaining, technician, expiry | Office. Client agent reads it |

Every update now has a home. The owner's day moved from passing messages along to dealing with the few things that actually need a decision.

| Area | Before | After |

## The same pattern fits any team that runs on chat

The industry doesn't matter much. What matters is where your people and customers already reply. Wherever that is, we build agents that capture, sort, chase and report behind it.
